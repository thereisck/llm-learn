# BM25 算法通俗讲义（给Java后端程序员看的）

> 目标：看完这篇，你能手写一个BM25搜索引擎。

---

## 1. BM25到底是干嘛的？

一句话：**给每个文档打分，看它跟查询词有多相关。**

你搜"RAG 检索优化"，BM25会算出每个chunk的分数，分数高的排前面。

跟向量检索的区别：
- **向量检索**：看"语义"——两段文字意思相近，就算用词不同也能匹配
- **BM25**：看"字面"——查询词在文档里出现了多少次、有多稀有

---

## 2. 先理解TF-IDF（BM25的前身）

### TF = 词频（Term Frequency）

一个词在文档里出现越多，说明这个文档跟这个词越相关。

> 例：搜"向量"，chunk A出现5次，chunk B出现1次 → A更可能讲向量

但问题是：**长文档天然词频高**（3000字的文档什么词都出现得多）。所以需要归一化。

### IDF = 逆文档频率（Inverse Document Frequency）

一个词越稀有，它出现在某文档里就越有价值。

> 例："BM25"只在3个chunk出现 → 包含"BM25"的chunk很珍贵
> 例："的"在所有chunk都出现 → 包含"的"毫无信息量

IDF的计算：`log(总chunk数 / 包含该词的chunk数)`

> 10个chunk，"BM25"出现在3个 → IDF = log(10/3) = 1.20（挺高）
> "的"出现在10个 → IDF = log(10/10) = 0（完全没用）

### TF-IDF = TF × IDF

结合起来：**一个词在文档里出现多（TF高）且本身很稀有（IDF高） → 这个词对这个文档很重要。**

---

## 3. BM25 = 升级版TF-IDF

BM25修复了TF-IDF的3个问题：

### 问题1：TF无限增长

TF-IDF里，词出现10次比出现5次重要2倍。但现实中，出现5次已经够了，出现10次不会比5次重要2倍——**TF应该有上限**。

**BM25的解法**：用饱和函数

```
TF部分 = f(qi, D) × (k1 + 1) / (f(qi, D) + k1)
```

- `f(qi, D)` = 词qi在文档D的出现次数
- `k1` = 控制饱和速度，默认1.2~2.0

**直观理解**：
- k1=1.2时，词出现1次→分数≈0.91，出现3次→≈1.04，出现10次→≈1.11
- **出现3次就接近满分了，出现更多不会继续涨很多** ✅

### 问题2：长文档天然TF高

3000字的chunk比500字的chunk词频高，但不一定更相关。

**BM25的解法**：长度归一化

```
归一化 = 1 - b + b × (|D| / avgdl)
```

- `|D|` = 当前文档长度（token数）
- `avgdl` = 所有文档的平均长度
- `b` = 归一化强度，默认0.75

**直观理解**：
- b=0 → 不归一化（忽略文档长度）
- b=1 → 完全归一化（长文档被严重惩罚）
- b=0.75 → 折中，长文档稍微吃亏但不至于被压死

> 例：avgdl=100词，当前chunk有200词
> 归一化因子 = 1 - 0.75 + 0.75 × (200/100) = 1.75
> 这个chunk的TF部分要除以1.75，等于说"你太长了，TF打折"

### 问题3：IDF不够精确

BM25用了更精确的IDF公式：

```
IDF(qi) = log((N - n(qi) + 0.5) / (n(qi) + 0.5))
```

- N = 总chunk数
- n(qi) = 包含词qi的chunk数
- +0.5是平滑项，防止极端情况（比如n=0时除零）

跟简单IDF的区别不大，就是更稳定。

---

## 4. BM25完整公式（组合起来）

```
BM25(D, Q) = Σ IDF(qi) × [f(qi, D) × (k1 + 1)] / [f(qi, D) + k1 × (1 - b + b × |D| / avgdl)]
```

翻译成大白话：

**对查询Q中的每个词qi**：
1. 算IDF(qi)：这个词有多稀有 → 稀有词权重高
2. 算TF部分：这个词在文档D出现几次 → 出现多分数高，但有上限（k1控制）
3. 算归一化：文档D比平均长度长多少 → 长文档打折（b控制）
4. 乘起来：IDF × TF饱和 / 归一化

**把所有查询词的分数加起来** → 就是文档D对查询Q的BM25总分。

## 5. 用你的RAG项目举例

假设你的知识库有10个chunk（来源rag-note.md），平均每个chunk 80词。

用户查询："BM25 检索 算法"

### 对chunk 3（120词，包含"BM25"出现2次、"检索"出现4次、"算法"出现1次）：

**第一步：算每个词的IDF**
- "BM25"：只出现在2个chunk → IDF = log((10-2+0.5)/(2+0.5)) = log(8.5/2.5) = 1.23
- "检索"：出现在6个chunk → IDF = log((10-6+0.5)/(6+0.5)) = log(4.5/6.5) = -0.37（出现太多chunk，反而降权）
- "算法"：出现在3个chunk → IDF = log((10-3+0.5)/(3+0.5)) = log(7.5/3.5) = 0.76

**第二步：算TF部分（k1=1.2）**
- "BM25"：2 × (1.2+1) / (2+1.2) = 2×2.2/3.2 = 1.375
- "检索"：4 × 2.2 / (4+1.2) = 4×2.2/5.2 = 1.692
- "算法"：1 × 2.2 / (1+1.2) = 2.2/2.2 = 1.0

**第三步：长度归一化（b=0.75，avgdl=80）**
- 归一化因子 = 1 - 0.75 + 0.75 × (120/80) = 0.25 + 1.125 = 1.375
- 这个chunk比平均长50%，TF要除以1.375

**第四步：每个词的BM25贡献**
- "BM25"：1.23 × 1.375 / 1.375 = 1.23
- "检索"：-0.37 × 1.692 / 1.375 = -0.45（出现太普遍，负贡献！）
- "算法"：0.76 × 1.0 / 1.375 = 0.55

**总分** = 1.23 - 0.45 + 0.55 = **1.33**

### 对chunk 7（60词，包含"BM25"出现1次，不含"检索"和"算法"）：

- "BM25"：IDF=1.23，TF=1×2.2/2.2=1.0，归一化=0.25+0.75×(60/80)=0.8125
  → 贡献 = 1.23 × 1.0 / 0.8125 = 1.51
- "检索"和"算法"：不出现，贡献=0

**总分** = 1.51

### 结果：chunk 7(1.51) > chunk 3(1.33)

chunk 7虽然只包含1个查询词，但它短（归一化惩罚小），而且"BM25"很稀有（IDF高），所以排名更靠前。

这就是BM25跟向量检索不同的地方——**它看的是精确匹配和词的稀缺性**。

## 6. 参数调优速查

| 参数 | 默认值 | 作用 | 调参建议 |
|------|--------|------|----------|
| k1 | 1.2~2.0 | TF饱和速度 | k1小→词频快速饱和（出现2-3次就够）；k1大→词频更线性增长 |
| b | 0.75 | 长度归一化强度 | b=0→忽略长度；b=1→完全归一化；中文短文本可降低到0.3~0.5 |
| k（RRF用的） | 60 | 排名平滑 | 不需要调，60是论文验证的最佳值 |

---

## 7. 对比总结

| 维度 | 向量检索 | BM25 |
|------|----------|------|
| 匹配方式 | 语义相似度 | 精确词匹配 |
| 强项 | 同义词/近义词/模糊意图 | 专有名词/术语/罕见词 |
| 弱项 | 精确术语可能漏召回 | 同义词完全不认 |
| 分数含义 | 0~1的cosine相似度 | 0~∞的权重分数 |
| 计算成本 | 需要Embedding模型 | 纯数学计算，极快 |
| 依赖 | Embedding API | 只需分词 |

**混合检索 = 取两者强项**：向量兜住语义，BM25兜住精确匹配。
