# Spring Boot 调用大模型接口项目说明文档

## 一、项目规划

### 1.1 项目目标
基于 Spring Boot 框架搭建一个可与大语言模型（LLM）进行交互的后端服务，实现接收前端请求并与大模型接口（如 SiliconFlow 平台）进行非阻塞的流式（Server-Sent Events, SSE）通信，实时返回推理结果。

### 1.2 技术栈与核心依赖
- **核心框架**：Spring Boot 4.0.5 (要求运行环境为 JDK 17 及以上)
- **网络客户端**：Spring WebFlux 提供的 `WebClient`（支持异步非阻塞及响应式编程）
- **数据序列化**：Jackson (`ObjectMapper`) 和 Fastjson2 (`JSONObject`)
- **其他辅助**：Lombok（简化代码）、Reactor（处理 `Mono`/`Flux` 响应式流）

### 1.3 阶段里程碑
1. **环境准备与项目启动排错**：解决 JDK 版本冲突、依赖包版本冲突问题。
2. **WebClient 核心组件配置**：解决 WebFlux 响应式客户端 Bean 未自动装配的拦截问题。
3. **大模型 API 接口联调与修正**：根据 SiliconFlow 的 OpenAI 兼容接口标准，修正 HTTP 请求路径与流式接收方式。
4. **服务规范化与文档沉淀**：根据排错和开发经验编写说明文档，供后续开发人员参考。

## 二、实施方案

本项目中调用大模型接口的核心代码位于 `ChatCompletionServiceImpl.java` 中。以下是具体实施要点：

### 2.1 运行环境要求 (JDK 17+)
项目使用的 Spring Boot 版本较新（4.x），其编译的 `.class` 字节码版本为 61.0。若在本地使用 JDK 8 (52.0) 启动，会抛出 `UnsupportedClassVersionError` 导致构建失败。因此，**必须将 IDE 和系统终端的 `JAVA_HOME` 切换至 JDK 17+**。

### 2.2 WebClient Bean 显式注入
由于项目中同时引入了 `spring-boot-starter-web` 和 `spring-boot-starter-webflux`，在混合使用 Servlet 与 Reactive 栈时，Spring Boot 可能不会默认自动装配 `WebClient.Builder`。
**解决方案**：必须显式地编写配置类，通过 `@Bean` 注解将其注入到 Spring 容器中，如 `WebClientConfig.java`：
```java
@Configuration
public class WebClientConfig {
    @Bean
    public WebClient.Builder webClientBuilder() {
        return WebClient.builder();
    }
}
```

### 2.3 大模型接口调用逻辑 (SSE 流式输出)
调用大模型接口的核心步骤如下：
1. **构造 WebClient**：
   - 设定基础 URL (`baseUrl`): `https://api.siliconflow.cn/v1`
   - 设定认证头 (`Authorization`): `Bearer <API_KEY>`
   - 设定接受格式 (`Accept`): `text/event-stream` (通知服务器需要 SSE 流式数据)
2. **发起 POST 请求并补充具体 URI**：
   - 必须通过 `.uri("/chat/completions")` 补全 OpenAI 标准接口路径。若缺失该路径，会直接请求到 BaseURL，导致抛出 `404 Not Found` 异常。
3. **响应式数据处理 (`Flux` 与 `Mono`)**：
   - `.bodyToFlux(String.class)`: 将服务器返回的流式块解析为字符串流。
   - `flatMap(processResponse)`: 对流中每一块数据进行拦截解析。如果是 `[DONE]` 标识，则代表流结束并触发数据库持久化；若是有效数据块，则解析 JSON 并组装为 `ServerSentEvent` 对象返回前端。
   - `.doOnCancel` 与 `.doOnTerminate`: 监听前端断开和正常结束事件。
   - `.onErrorResume`: 处理诸如网络异常或解析异常等情况，统一返回友好报错。
